# Аналитика продаж

Локальное приложение на Go с HTML-интерфейсом для анализа прибыльности первой таблицы книги Excel. Запускается как Windows-программа и открывает интерфейс в браузере по умолчанию. Исходная книга обрабатывается на компьютере пользователя и не отправляется на сервер.

> **Важно о данных.** Книга Excel для приложения по-прежнему отсутствует: файлов `.xlsx`, `.xlsm` или `.xls` в репозитории нет, поэтому прибыльность «первой таблицы» пока не рассчитана. При этом 19.10.2026 для анализа была получена PDF-ведомость ТМЦ за октябрь 2025 — октябрь 2026; она разобрана отдельно, результаты — в разделе ниже и в каталоге [`reports/`](reports/). Исходный PDF в репозиторий не добавлялся.

## Анализ продаж по ведомости ТМЦ (PDF)

По приложенной ведомости 1С «Ведомость по остаткам ТМЦ на складах» (склад «Кореличи», 111 позиций, 01.10.2025–19.10.2026) подготовлены:

- [`reports/analiz-prodazh-2025-10_2026-10.md`](reports/analiz-prodazh-2025-10_2026-10.md) — аналитический отчёт: динамика и сезонность, структура ассортимента, ABC/XYZ, остатки и дефицит, качество данных, рекомендации.
- [`reports/dashboard.html`](reports/dashboard.html) — автономный интерактивный дашборд (без внешних библиотек и интернета): KPI, графики, матрица ABC×XYZ, таблица 111 SKU с поиском, фильтрами и сортировкой.
- [`reports/vedomost_2025-10_2026-10.csv`](reports/vedomost_2025-10_2026-10.csv) — разобранные данные по позициям и месяцам.
- [`reports/summary.json`](reports/summary.json) — все агрегаты и расчётные метрики по 111 позициям (источник для дашборда).

Ключевые цифры: 2 955 упак. / 4 986 л за 13 месяцев; 89,2% продаж — март–сентябрь; 45 позиций ниже минимального резерва (дефицит 116 упак.); 10 позиций отсутствуют при наличии спроса; 7 позиций — мёртвый остаток. В ведомости нет цен, поэтому выручка, прибыль и маржинальность не рассчитывались. Сумма месячных колонок расходится с колонкой «Расход» на 16,5% — это ограничение интерпретации описано в отчёте.

Инструменты разбора и пересборки (Python 3.10+, `pdfplumber`):

```bash
python tools/parse_vedomost.py "Ведомость мав.pdf" /tmp/ved.json
python tools/build_analysis.py /tmp/ved.json reports
python tools/build_dashboard.py reports/summary.json tools/dashboard_template.html reports/dashboard.html
python tools/serve_report.py          # http://localhost:8000/ → dashboard.html
```

Скрипты не входят в Go-приложение и не влияют на его сборку; сторонние Go-модули по-прежнему не используются.

## Возможности

- Открыть книгу `.xlsx` или `.xlsm` и автоматически выбрать первую структурированную Excel-таблицу. Если формальных таблиц в книге нет — взять используемый диапазон первого непустого видимого листа.
- Найти строку заголовков (в обычном диапазоне — в первых 25 строках) и распознать русские и английские названия столбцов.
- Рассчитать выручку, себестоимость, прибыль и маржинальность, определить строки с убытком и показать до пяти лучших и худших позиций.
- Поддержать цену продажи/закупки и прибыль за единицу при наличии столбца количества.
- Исключить строку `Итого` / `Total`, чтобы не складывать итог повторно.
- Показать найденные соответствия столбцов и предупреждения о неполных данных или неоднозначном расчёте.

Поддерживаются `.xlsx` и `.xlsm`. Старый бинарный формат `.xls`, файлы `.xlsb` и внешние связи не поддерживаются. Формулы Excel берутся из сохранённых в книге результатов; перед загрузкой пересчитайте и сохраните книгу в Excel, если формулы изменялись.

## Запуск в Windows

1. Откройте **GitHub → Actions → Build Windows application**.
2. Выберите последний успешный запуск workflow и скачайте artifact **`AnalitikaSales-windows-amd64`**.
3. Распакуйте архив и запустите `AnalitikaSales-windows-amd64.exe`. Приложение откроет HTML-интерфейс в браузере.
4. Перетащите Excel-файл в окно или выберите его через диалог, затем нажмите **«Анализировать таблицу»**.
5. Кнопка **«Завершить»** останавливает локальное приложение.

Приложение слушает случайный свободный порт только на `127.0.0.1`; загрузка ограничена 50 МиБ. Внешние веб-ресурсы и сторонние сервисы не используются.

## Сборка и тесты для разработчика

Нужен Go 1.22 или новее:

```sh
go test ./...
go run ./cmd/analitika-sales
```

При запуске автоматически открывается браузер. Для разработки без автоматического открытия (URL будет выведен в консоль):

```sh
go run ./cmd/analitika-sales -no-browser
```

Чтобы собрать Windows x64 executable вручную на Windows:

```powershell
New-Item -ItemType Directory -Force dist | Out-Null
go build -trimpath -ldflags="-s -w -H=windowsgui" -o dist/AnalitikaSales-windows-amd64.exe ./cmd/analitika-sales
```

Проект не использует сторонние Go-модули: чтение XLSX реализовано стандартной библиотекой Go.

## GitHub Actions

Workflow `.github/workflows/build-windows.yml` автоматически запускается при push в `main` или `arena/**`, при pull request в `main` и вручную через `workflow_dispatch`. ## Как считается прибыльность

1. Если распознан столбец **прибыли**, используется его сумма.
2. Иначе при наличии выручки и себестоимости считается `прибыль = выручка − себестоимость`.
3. Если есть выручка и столбец процента маржи — `прибыль = выручка × маржа / 100`.
4. Если отсутствуют выручка или себестоимость, но есть прибыль, недостающее значение может быть выведено из `выручка = себестоимость + прибыль` или `себестоимость = выручка − прибыль`.
5. Итоговая маржинальность рассчитывается как `прибыль / выручка × 100` по строкам, где найдены обе величины.

Названия столбцов и ограничения автоматического сопоставления описаны в [`docs/analysis-methodology.md`](docs/analysis-methodology.md). Отчёт предназначен для управленческой оценки, не заменяет бухгалтерскую или налоговую отчётность.
