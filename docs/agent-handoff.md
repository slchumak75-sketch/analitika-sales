## Архитектура

- `cmd/analitika-sales/main.go` — точка входа, временный loopback HTTP-сервер на свободном порту и открытие браузера.
- `internal/app/server.go` — локальный HTTP API, загрузка файла, лимиты и security headers.
- `internal/app/web/index.html` — автономный HTML/CSS/JS интерфейс, внедряемый в executable директивой `go:embed`.
- `internal/xlsx/reader.go` — чтение OOXML из ZIP стандартной библиотекой Go; таблицы Excel, relationships, shared strings, inline strings, кешированные результаты формул.
- `internal/analysis/analyze.go` — распознавание заголовков, числовой парсер, расчёты и предупреждения.
- `internal/*/*_test.go` — модульные тесты ZIP/XLSX, расчётов и HTTP-интерфейса.
- `.github/workflows/build-windows.yml` — Windows x64 runner, `go test ./...`, сборка GUI executable и artifact `AnalitikaSales-windows-amd64`.
- Внешние Go-модули не используются.

## Проверки и ограничения среды

Во время разработки в sandbox команда `go version` завершилась ошибкой `go: command not found`; поэтому локально Go-код не был скомпилирован или прогнан через `go test`. Последняя проверка GitHub Actions **успешна**: run `39238829638` на commit `54fff0c` выполнил `go test ./...`, собрал Windows x64 executable и загрузил artifact `AnalitikaSales-windows-amd64` (30 дней хранения). Первый запуск выявил ошибку в разборе чисел с валютным суффиксом; исправление покрыто тестом. После следующих изменений обязательно повторить проверку в Actions.

Windows executable собирается с `-H=windowsgui` и открывает HTML в браузере по умолчанию; это не WebView-окно. Кнопка «Завершить» вызывает локальный endpoint остановки. Для финальной приёмки всё равно нужен запуск artifact на Windows.

## Известные нюансы, которые важно перепроверить на реальном файле

- Автоматическое сопоставление заголовков эвристическое; приоритет у первой распознанной колонки каждого типа с самым специфичным совпадением.
- В обычном диапазоне заголовок ищется среди первых 25 строк. Для Excel Table заголовок считается первой строкой Table.
- В формульных ячейках используется только сохранённый Excel cached value; приложение не пересчитывает формулы.
- XLSX-парсер безопасно ограничивает распаковку и ширину/высоту диапазона; экзотические OOXML-книги могут требовать дополнительной обработки.
- Если в книге несколько формальных Excel Tables на разных листах, выбирается первая Table по порядку видимых листов, прежде чем искать запасной диапазон.
