## Архитектура

### Go-приложение (исходная задача)

- `cmd/analitika-sales/main.go` — точка входа, временный loopback HTTP-сервер на свободном порту, открытие браузера.
- `internal/app/server.go` — локальный HTTP API, загрузка файла, лимиты, security headers.
- `internal/app/web/index.html` — автономный HTML/CSS/JS интерфейс, встроенный через `go:embed`.
- `internal/xlsx/reader.go` — чтение OOXML из ZIP стандартной библиотекой Go; shared strings,
  inline strings, кешированные результаты формул, таблицы Excel.
- `internal/analysis/analyze.go` — распознавание заголовков, числовой парсер, расчёт прибыли
  и маржинальности, предупреждения.
- `.github/workflows/build-windows.yml` — `go test ./...`, сборка Windows x64 `.exe`, artifact
  `AnalitikaSales-windows-amd64`. Внешние Go-модули не используются.

### Анализ PDF-ведомости (новый контур)

- `tools/parse_vedomost.py` — парсер PDF (`pdfplumber`): колонки разнесены по группам страниц
  (1/4/7/10 — номенклатура, 2/5/8/11 — приход/расход/остаток/резерв/окт–апр,
  3/6/9/12 — май–окт). Строки склеиваются по порядку; проверяется баланс.
- `tools/build_analysis.py` — расчёт литров, ABC (80/95 по литрам), XYZ (CV апреля–сентября,
  0.5/1.0), покрытия, статусов, дефицита/профицита, качества данных; пишет CSV и `summary.json`.
- `tools/build_dashboard.py` + `tools/dashboard_template.html` — самодостаточный HTML-дашборд
  (данные встроены, внешних библиотек нет); адаптивная вёрстка для 390/1024/1440 px.
- `tools/serve_report.py` — раздача `reports/` на `0.0.0.0:8000` с редиректом `/` → `dashboard.html`
  (нужна для live preview в Arena; обычный `python -m http.server` тоже работает).
- `reports/` — отчёт, дашборд, CSV, агрегаты.
- Зависимости Python: `pdfplumber` (устанавливались в sandbox через `/tmp/venv`, в репозиторий
  не добавлялись). Go-сборка от них не зависит.

## Следующие шаги

1. **Сверить семантику месячных колонок в 1С.** Сумма месяцев — 2 955 упак., «Расход» — 2 537
   (+16,5%); в 37 строках совпадает, в 74 месяцы больше, в 0 — меньше; в 30 строках продажи
   превышают «начальный остаток + приход». Выяснить, какой показатель выводится в месячных
   колонках, и проверить отрицательные остатки/продажи с других складов.
2. **Получить книгу Excel** для исходного Go-приложения и/или отчёт с суммами («Реализация ТМЦ»),
   чтобы посчитать выручку, прибыль и маржинальность. Без цен это невозможно — в отчёте это
   явно зафиксировано.
3. **Проверить выводы на актуальной выгрузке**: октябрь 2026 неполный (1–19), возможна задержка
   выгрузки; сезонность нельзя отделить от тренда без второго года.
4. **Пересчитать минимальные резервы** по ABC/XYZ и сезонности: сейчас норматив 0–6 упак. даёт
   покрытие от 0,2 до 18 месяцев; 19 SKU защищены меньше половины месяца, 19 — больше трёх месяцев.
5. При изменении формата PDF расширить `tools/parse_vedomost.py` и добавить регрессионную
   проверку (111 строк + баланс). При изменении методики обновить отчёт и дашборд.
6. Проверить Windows artifact на Windows после изменений Go-кода.

## Как пересобрать анализ

```bash
python tools/parse_vedomost.py "Ведомость мав.pdf" /tmp/ved.json
python tools/build_analysis.py /tmp/ved.json reports
python tools/build_dashboard.py reports/summary.json tools/dashboard_template.html reports/dashboard.html
python tools/serve_report.py            # http://localhost:8000/ → dashboard.html
```

Проверка JS без браузера:

```bash
node -e "const fs=require('fs');const h=fs.readFileSync('reports/dashboard.html','utf8');fs.writeFileSync('/tmp/dash.js',h.match(/<script>([\s\S]*)<\/script>/)[1])"
node --check /tmp/dash.js
```

## Известные нюансы

- В ведомости нет цен: все выводы — про количество и литры, не про деньги.
- Литры — оценка: «N л» как есть, «N кг» ÷ 1,35 кг/л; для двух позиций объём восстановлен
  по названию («FLAGMAН 5» = 5 л; «вишневая 0,9 (0,8кг)» = 0,9 л). Одна позиция без размера
  исключена из литров.
- Артикул заполнен у 1 позиции из 111; единицы измерения разные (шт/банка/ведро); в названиях
  есть опечатки. Всё это перечислено в разделе 7 отчёта.
- Исходный PDF в репозиторий не добавлялся; CSV и HTML содержат разобранные количественные данные.
- Go-код и Python-инструменты независимы; Python-скрипты не участвуют в Go-сборке и Actions.
- `summary.json` → `halves.season_mar_sep` — это март–сентябрь 2026 (2 635 упак., 89,2%);
  неполный октябрь 2026 (81 упак., 2,7%) в сезон не включён. Ранее ключ назывался
  `season_mar_oct`, что путало подпись «март–октябрь».
- `COLOR_MAP` в `build_analysis.py`: белые варианты («белая», «белая гл.», «белая мат.») уже
  сведены в один цвет; коричневые подтона ПФ-266 (св.-, зол.-, жёл.-корич.) оставлены
  раздельно, т.к. это разные позиции номенклатуры. Дополнительная чистка не требуется.
- Доли цветов в отчёте и дашборде считаются от объёма эмалей (4 408,1 л), а `litre_share`
  в `summary.json` — от всех литров (12,5% для белой). Это осознанное различие, не ошибка.
